# Avito: кандидатогенерация для поиска услуг (Recall@50)

Решение тестового задания: по поисковому запросу выбрать из корпуса `benchmark_items.parquet` до 50 объявлений так, чтобы в них попало как можно больше подходящих.

Весь код, EDA, валидация, подбор весов, проверки и описание решения находятся в ноутбуке [solution.ipynb](solution.ipynb). Ноутбук сохранен вместе с выводами последнего запуска.

## Результат

| Выборка | Recall@50 |
|---|---|
| Валидация A (на ней подбирались веса) | 0.9208 |
| Отложенная валидация B (честная оценка) | 0.9066 |

Как менялось качество по шагам (начальные веса, до подбора):

| Шаг | A | B |
|---|---|---|
| BM25 по тексту | 0.3920 | 0.3921 |
| + BM25 по заголовку | 0.4235 | 0.4354 |
| + локация | 0.8732 | 0.8504 |
| + фильтры | 0.8916 | 0.8703 |
| + подкатегория | 0.8974 | 0.8927 |
| + эмбеддинги | 0.9003 | 0.8918 |
| + расширение запроса | 0.9021 | 0.8926 |
| + расстояние | 0.9085 | 0.9003 |
| подбор весов | 0.9208 | 0.9066 |

## Подход

Для каждого запроса скор считается сразу по всем объявлениям корпуса как взвешенная сумма сигналов, берутся 50 лучших:

- **BM25** по заголовку + описанию + параметрам объявления (слова со стеммингом Snowball);
- **локация**: log P(локация объявления | локация поиска), вероятности посчитаны по train. В 83% пар train локации совпадают, остальное в основном "регион -> город";
- **расстояние** от типичной точки локации поиска до координат объявления, помогает для пар локаций, которых не было в train;
- **фильтры**: "Вид услуги ..." и "Тип услуги ..." из `search_infm_params_text` сверяются с `item_infm_params_text` (в train совпадают в 98% пар);
- **подкатегория**: распределение `item_microcat_id` по 20 самым похожим запросам из train;
- **расширение запроса**: заголовки объявлений, выбранных по похожим запросам в train, сравниваются с заголовками корпуса (TF-IDF);
- **эмбеддинги** `sergeyzh/rubert-tiny-turbo` для запроса и объявления (заголовок + начало описания).

Веса подобраны перебором по координатам на валидации A, итоговая оценка на B.

## Валидация

- `train.parquet` делится по уникальным комбинациям всех `search_*` полей (12% в валидацию), чтобы одна комбинация не попала в обе части.
- Все объявления, выбранные по одной комбинации, объединены в один запрос с несколькими релевантными `item_id`.
- В benchmark у каждого запроса свой текст, и 37% текстов встречались в train. Валидационные выборки собраны так же: по одной комбинации на текст и 37% знакомых текстов.
- Поиск на валидации идет по всему `benchmark_items` плюс релевантные объявления валидационных запросов (около 195 тыс. объявлений).
- Вся статистика по train на валидации считается только по обучающей части.

## Как запустить

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Linux / macOS:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Положить `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet` в папку `dataset/` и выполнить ноутбук целиком (Run All) или из консоли:

```bash
jupyter nbconvert --to notebook --execute --inplace solution.ipynb --ExecutePreprocessor.timeout=-1
```

В конце ноутбук пишет `answer.csv` в корень репозитория. На 8-ядерном CPU без GPU прогон с нуля занимает около 40 минут, из них около 11 минут уходит на эмбеддинги. Эмбеддинги кэшируются в `cache/`. При первом запуске модель `sergeyzh/rubert-tiny-turbo` (~120 МБ) скачивается с Hugging Face, дальше все работает локально, без обращений к внешним API.

## Проверки ответа

В разделе 10 ноутбука `answer.csv` читается обратно и проверяется: две колонки `query_id,answer`, строка на каждый `query_id` без лишних и повторов, не больше 50 `item_id` без повторов, все `item_id` есть в корпусе, разделитель ровно один пробел, ID остались строками. Там же разобраны пограничные случаи: пустые фильтры, запросы из одного слова, запросы без совпадений по словам, редкие категории, дубли объявлений, необычные символы.

## Воспроизводимость

Случайность есть только в сплите (`SEED = 42`), модель эмбеддингов используется без дообучения. Ноутбук дважды запускался с нуля (с удалением кэша эмбеддингов) и оба раза дал один и тот же `answer.csv`, md5 печатается в конце ноутбука: `50fe37d207d69d364c109960ba74979d`. Проверялось на Windows 10, Python 3.14, версии библиотек в `requirements.txt`. На другом железе или с другими версиями PyTorch эмбеддинги могут отличаться в последних знаках, и тогда могут поменяться отдельные объявления на границе топ-50.

## Библиотеки и модели

pandas, numpy, scipy, pyarrow, scikit-learn (CountVectorizer, TfidfVectorizer), snowballstemmer, PyTorch, sentence-transformers, модель [sergeyzh/rubert-tiny-turbo](https://huggingface.co/sergeyzh/rubert-tiny-turbo).
