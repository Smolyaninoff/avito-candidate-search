# Avito: кандидатогенерация для поиска услуг (Recall@50)

Решение тестового задания: по поисковому запросу выбрать из корпуса `benchmark_items.parquet` до 50 объявлений так, чтобы в них попало как можно больше подходящих.

Весь код, EDA, валидация, дообучение модели, подбор весов, проверки и описание решения находятся в ноутбуке [solution.ipynb](solution.ipynb). Ноутбук сохранен вместе с выводами последнего запуска.

## Результат

Recall@50 на своей валидации (подробности ниже):

| Версия | A (подбор весов) | B (отложенная) | Платформа |
|---|---|---|---|
| Первая версия | 0.8924 | 0.8838 | 0.877 |
| Текущая версия | 0.9112 | 0.8942 | |

Первая версия на старой, более легкой валидации получала 0.907, а на платформе 0.877. После разбора валидация была переделана (раздел 6 ноутбука): на новой валидации первая версия получает 0.884, то есть близко к платформе. Текущая версия улучшена уже на новой валидации.

## Подход

Для каждого запроса скор считается сразу по всем объявлениям корпуса как взвешенная сумма сигналов, берутся 50 лучших:

- **BM25** по заголовку + описанию + параметрам объявления и отдельно по заголовку (слова со стеммингом Snowball);
- **локация**: log P(локация объявления | локация поиска), вероятности посчитаны по train. В 83% пар train локации совпадают, остальное в основном "регион -> город";
- **нелокальность запроса**: по похожим запросам из train считается, как часто люди выбирали объявление в другом месте (базы отдыха, межгород, онлайн-услуги). Для таких запросов штраф за локацию ослабляется;
- **расстояние** от типичной точки локации поиска до координат объявления;
- **фильтры**: "Вид услуги ..." и "Тип услуги ..." из `search_infm_params_text` сверяются с `item_infm_params_text` (в train совпадают в 98% пар);
- **подкатегория**: распределение `item_microcat_id` по 20 самым похожим запросам из train;
- **расширение запроса**: заголовки объявлений, выбранных по похожим запросам в train, сравниваются с заголовками корпуса (TF-IDF);
- **эмбеддинги** готовой модели `sergeyzh/rubert-tiny-turbo`;
- **эмбеддинги дообученной модели**: та же `rubert-tiny-turbo`, дообученная на парах "запрос - выбранное объявление" из train (одна эпоха на CPU, около 17 минут).

Веса подобраны перебором по координатам на валидации A, итоговая оценка на B.

## Валидация

- `train.parquet` делится по уникальным комбинациям всех `search_*` полей (40% в валидацию), чтобы одна комбинация не попала в обе части.
- Все объявления, выбранные по одной комбинации, объединены в один запрос с несколькими релевантными `item_id`.
- В benchmark у каждого запроса свой текст, и 37% текстов встречались в train. Валидационные выборки A и B (по ~3000 запросов) собраны так же: по одной комбинации на текст и 37% знакомых текстов.
- Корпус benchmark собран вокруг самих запросов: рядом с каждым запросом (в той же локации и по смыслу) много похожих объявлений. Поэтому в корпус для валидации кроме `benchmark_items` и релевантных объявлений добавляются "похожие" объявления: для каждого валидационного запроса 30 лучших по BM25 и 30 лучших по эмбеддингам из подходящих локаций, только из объявлений, которых нет в обучающей части. Всего около 270 тыс. объявлений.
- Вся статистика по train и дообучение модели на валидации используют только обучающую часть.

## Как запустить

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Linux / macOS:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Положить `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet` в папку `dataset/` и выполнить ноутбук целиком (Run All) или из консоли:

```bash
jupyter nbconvert --to notebook --execute --inplace solution.ipynb --ExecutePreprocessor.timeout=-1
```

В конце ноутбук пишет `answer.csv` в корень репозитория. На 8-ядерном CPU без GPU прогон с нуля занимает около 85 минут: эмбеддинги примерно 23 минуты, дообучение модели 17 минут, прогон валидации 30 минут. Эмбеддинги и дообученная модель сохраняются в `cache/`, повторный прогон около 45 минут. При первом запуске модель `sergeyzh/rubert-tiny-turbo` (~120 МБ) скачивается с Hugging Face, дальше все работает локально, без обращений к внешним API.

## Проверки ответа

В разделе 12 ноутбука `answer.csv` читается обратно и проверяется: две колонки `query_id,answer`, строка на каждый `query_id` без лишних и повторов, не больше 50 `item_id` без повторов, все `item_id` есть в корпусе, разделитель ровно один пробел, ID остались строками. Там же разобраны пограничные случаи: пустые фильтры, запросы из одного слова, запросы без совпадений по словам, редкие категории, дубли объявлений, необычные символы.

## Воспроизводимость

Случайность есть в сплите и в дообучении модели. Везде зафиксирован `SEED = 42`, порядок батчей задается через `random.Random(SEED)`, на время обучения включен детерминированный режим PyTorch. Ноутбук дважды запускался с нуля (с удалением кэша эмбеддингов и дообученной модели) и оба раза дал один и тот же `answer.csv`, md5 печатается в конце ноутбука: `94469756af041719c372c036227ec9db`. Проверялось на Windows 10, Python 3.14, версии библиотек в `requirements.txt`. На другом железе или с другими версиями PyTorch вычисления с плавающей точкой могут отличаться в последних знаках, и тогда могут поменяться отдельные объявления на границе топ-50.

pandas, numpy, scipy, pyarrow, scikit-learn (CountVectorizer, TfidfVectorizer), snowballstemmer, PyTorch, sentence-transformers, модель [sergeyzh/rubert-tiny-turbo](https://huggingface.co/sergeyzh/rubert-tiny-turbo).
